# 与现有工具的定位比较

作者：LLR6

核对日期：2026-10-02。这里讨论公开文档描述的能力与边界，不声称市场上的工具普遍没有风控、模拟交易或审计。

| 参考 | 已有能力 / 官方指出的边界 | 本项目的具体选择 |
| --- | --- | --- |
| [Freqtrade lookahead-analysis](https://docs.freqtrade.io/en/latest/lookahead-analysis/) | 通过多次回测对照发现未来数据泄漏；未触发的信号不能被完整验证 | 为固定策略测试未来数据扰动不影响历史订单，并将每笔信号日期保留在账本 |
| [Alpaca Paper Trading](https://docs.alpaca.markets/us/v1.4.2/docs/paper-trading) | 有实时模拟环境；官方列出市场冲击、延迟滑点、订单队列等模拟限制 | 无账户依赖的本地日线账户；显式写明自己的成交假设，不把模拟收益当实盘证据 |
| 独立研究脚本到日常使用的交接 | 这是本项目针对的工作流问题，不是对所有竞品的评价 | 一个 CLI 完成 CSV 标准化、数据质检、持久账户、调仓草案、静态工作台和审计 |

v0.2 的实用性来自降低复现和连续使用成本：中英文 CSV、SQLite 账户、重复/并发导入幂等、历史修订拒绝、过期数据拒绝、手数/最低费用/最小金额约束、说明交易原因、可分享的静态工作台。

它不是这些成熟系统的全面替代，也没有独创性或真实获利证据。优先补齐的下一步是交易所日历、时间戳与数据来源、公司行动以及真实交易限制，而不是增加无法追溯的 AI 买卖理由。
